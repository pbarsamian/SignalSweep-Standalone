# Display library decision (C6-Touch-LCD-1.47)

Decision: **LovyanGFX 1.3.0 with an in-repo panel class** (`src/boards/c6_touch147/lgfx_c6.h`) that carries Waveshare's
own init sequence. Not TFT_eSPI.

## What I checked

| Question | Evidence |
|---|---|
| What does Waveshare drive the panel with? | Their Arduino demo (`ESP32-C6-Touch-LCD-1.47-Demo.zip`, `examples/01_gfx_helloworld`) uses **Arduino_GFX v1.5.9 `Arduino_ST7789`** (172x320, column offset 34) plus a custom `lcd_reg_init()` register list. It does not use a JD9853 class. |
| Does Arduino_GFX have a JD9853 class? | No. `grep -ri jd9853` over the demo's bundled GFX_Library_for_Arduino 1.5.9 `src/` finds nothing. |
| Does LovyanGFX have a JD9853 class? | Yes, `Panel_JD9853.hpp` in 1.3.0, but it is **240x240, for M5ChainCaptain**, and its register values differ from Waveshare's list. It is not usable as is for this 172x320 panel. |
| Does LovyanGFX run on the C6? | 1.3.0 `Bus_SPI.inl` has an explicit `CONFIG_IDF_TARGET_ESP32C6` branch and its CI matrix lists `esp32c6`. The build and the board are the real test (see result below). |
| Is TFT_eSPI an option? | It has no JD9853/ST7789 172x320 profile for this board that I could show works on the C6 toolchain, and the manifest forbids it unless shown. Not pursued. |

## Why LovyanGFX over Arduino_GFX

The existing UI (`src/ui.cpp`, 1369 lines) is written against the TFT_eSPI API: `drawString(str, x, y, font)`,
`setTextDatum`, `textWidth`, `color565`, `fillTriangle`, `fillRect`, `drawFastHLine`, and so on. LovyanGFX's API
is close to that, so Phase 4's `Display` shim should be small. Arduino_GFX is an Adafruit_GFX-style API with a
different text model, which would mean touching a lot more of `ui.cpp`. Both libraries can carry Waveshare's init
list, so the choice comes down to the UI cost. (The shim size is a Phase 4 estimate, not measured.)

## How the panel is described

- Panel 172x320, controller RAM 240x320, `offset_x = 34` (symmetric, so it holds in rotated modes too).
- Init: Waveshare's `lcd_reg_init()` translated mechanically into LovyanGFX's command-list format
  (33 commands, generated by script from the demo source, not retyped). Final `0x21` (inversion on) matches
  `invert = true`.
- Bus: SPI2 (FSPI), SCK 1, MOSI 2, DC 15, CS 14, RST 22, BL 23 (LEDC via `Light_PWM`), 40 MHz write. MISO is
  not given to the LCD (GPIO3 is the TF slot's MISO). `bus_shared = true` for the TF slot on the same SCK/MOSI.
- Landscape (Paul's choice): `setRotation(1)`, so the UI sees 320x172.

## Status

Offset, colours and inversion are confirmed on hardware (below). Text direction at rotation 1 is not yet confirmed.

### Bring-up result
Built and flashed on the board 2026-11-19 (LovyanGFX 1.3.0, Arduino 3.3.12 / IDF 5.5.5). Paul reports the 1-px border complete on all sides
and the colour bars in order, so the offset, init list, inversion and RGB order are right. Details and the unconfirmed items (text
orientation, touch scale) are in `docs/port/BRINGUP_RESULTS.md`.
